# Engineering Documentation Method

GitHub contains the reproducible technical evidence. LinkedIn summarizes and links to verified work.

## For every project

1. **Question and objective:** Identify what is being tested.
2. **Theory and assumptions:** Explain equations, models and constraints.
3. **Setup:** Name tools, versions, components, settings and input data.
4. **Reproduction:** Give numbered simulation or test instructions.
5. **Results:** Attach source files, correctly labeled figures and any raw data.
6. **Discussion:** Compare predictions with results; describe errors.
7. **Conclusion:** State what was learned and what remains uncertain.
8. **References:** Attribute papers, courses, code, and datasets.

## File conventions

- Reports: YYYY-MM-DD-topic.md
- Figures: topic-plot.png
- Data: topic-data.csv
- Source: retain original .asc, .cir, .v, .sv, .py and related files

Never commit credentials, private data, confidential client content, or third-party material without appropriate rights. Describe unfinished work as planned or in progress.
